================================================================================
                        CONTINUOUS LEARNING SYSTEM
================================================================================

HOW IT WORKS:
1. User submits email for analysis
2. Model makes prediction with confidence score
3. If confidence ≥ 85%, automatically labeled and stored
4. Examples accumulate in training_examples.json
5. Every 30 examples, automatic retraining triggered
6. New model validated (accuracy > 70%)
7. If valid, deployed as new version
8. Model improves continuously

RETRAINING TRIGGERS (Any one activates retraining):
- 30 new examples accumulated
- 5+ user corrections provided
- 20+ auto-labeled examples collected
- 15+ high-confidence examples accumulated

AUTO-LABELING STRATEGIES:
1. High Confidence: ≥85% confidence → Auto-label
2. Medium Confidence + Indicators: ≥60% + 2+ BEC indicators → Auto-label phishing
3. Low Phishing + High Confidence: ≤20% phishing + 80% confidence → Auto-label legitimate

TRAINING DATA STORAGE:
- Location: web/data/
- Files:
  * training_examples.json - Collected examples with metadata
  * model_versions.json - Retraining history
  * model_performance.json - Performance metrics

================================================================================
                        TROUBLESHOOTING
================================================================================

PROBLEM: Model not learning
SOLUTION:
- Check ACTIVE_LEARNING_ENABLED = True
- Verify web/data/ directory exists and is writable
- Check console logs for errors

PROBLEM: Retraining not triggered
SOLUTION:
- Ensure you have ≥ 25 examples (MIN_EXAMPLES_FOR_RETRAIN)
- Check if 30 examples threshold reached (RETRAIN_THRESHOLD)
- Verify user corrections are being recorded

PROBLEM: Model performance degrading
SOLUTION:
- Increase AUTO_LABEL_CONFIDENCE_THRESHOLD to 0.90
- Manually review training examples in training_examples.json
- Consider resetting training data if corrupted
